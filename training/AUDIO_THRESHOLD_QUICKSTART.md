# 听觉大师 - 阈值刷新功能快速指南

## 🎯 功能说明

用户可以调整灵敏度阈值后，**无需重新上传音频或重新推理**，即可立即刷新所有历史记录的判定结果。

---

## 🚀 使用方法

### 步骤 1: 上传音频文件
- 上传一个或多个 .wav 音频文件
- 系统使用当前灵敏度（默认70%）进行检测

### 步骤 2: 查看初始结果
- 查看检测结果和异常数量
- 如果觉得灵敏度不合适，进行调整

### 步骤 3: 调整灵敏度
- 拖动"灵敏度"滑块（0-100%）
- 灵敏度越高 → 越容易判定为异常
- 系统自动显示**蓝色"应用阈值"按钮**

### 步骤 4: 应用新阈值
- 点击"应用阈值"按钮
- 所有历史记录的判定结果**立即更新**
- 异常数量统计自动刷新

---

## 💡 工作原理

```
原始数据（不变）          用户输入           计算结果（会变）
┌────────────┐           ┌──────┐           ┌──────────┐
│  Score     │           │ 阈值  │           │ 判定结果  │
│  (0-1)     │    +      │(0-100)│    →     │ 是否异常  │
│  模型输出  │           │      │           │ 状态/级别 │
└────────────┘           └──────┘           └──────────┘
```

- **Score**: 模型的原始输出，永不改变
- **阈值**: 用户调整的灵敏度参数
- **判定**: 根据 Score 和阈值重新计算

## 🎨 UI 交互

### 按钮显示条件
- ✅ 阈值与上次应用的不同
- ✅ 存在历史记录
- 如果都满足 → 显示蓝色"应用阈值"按钮

### 按钮位置
```
[━━━━灵敏度━━━━] [70%] [应用阈值]
```

### 按钮状态
- **未应用**: 蓝色背景，显示 "应用阈值"
- **应用中**: 加载动画，显示 "应用中..."
- **已应用**: 按钮消失

## 🔍 判定逻辑

### 阈值转换
```
用户输入: 灵敏度 = 70%
转换公式: normalityThreshold = 1 - (70 / 100) = 0.3
判定规则: score < 0.3 → 异常
```

### 状态细分

#### 异常状态
- Score < 0.3 → **严重异常** (CRITICAL, Very High)
- Score < 0.4 → **明显异常** (HIGH, High)
- 其他异常 → **中度异常** (MEDIUM, Medium)

#### 正常状态
- Score > 0.7 → **完全正常** (PERFECT, Very High)
- Score > 0.5 → **基本正常** (NORMAL, High)
- 其他正常 → **可疑** (SUSPICIOUS, Medium)

---

## ⚠️ 注意事项

1. **检测失败的记录不会被更新**
   - 如果某个文件检测失败（score = 0）
   - 应用阈值时会跳过该记录

2. **阈值不影响新上传的文件**
   - 新上传的文件使用当前阈值进行检测
   - 如果再调整阈值，需要点击"应用阈值"

3. **刷新页面后阈值不丢失**
   - 更新后的判定结果会自动保存
   - 刷新页面后结果仍然是最新的

## 🎓 使用建议

### 场景 1: 首次检测
1. 使用默认灵敏度（70%）上传音频
2. 如果异常太多 → 降低灵敏度（如 50%）
3. 如果异常太少 → 提高灵敏度（如 85%）

### 场景 2: 批量调试
1. 批量上传 50-100 个音频样本
2. 尝试不同阈值（30%, 50%, 70%, 90%）
3. 找到最佳平衡点（既不漏报，也不误报）

### 场景 3: 定期检测
1. 使用经过验证的阈值（如 65%）
2. 定期上传新音频文件
3. 观察异常趋势，必要时微调阈值

## 🐛 故障排除

### 问题: 按钮不显示
- **原因**: 阈值未改变或无历史记录
- **解决**: 调整灵敏度滑块，或先上传音频文件

### 问题: 点击按钮无反应
- **原因**: 可能在应用中
- **解决**: 等待"应用中..."动画完成

### 问题: 应用后结果未更新
- **原因**: 浏览器缓存问题
- **解决**: 刷新页面，检查结果是否持久化
